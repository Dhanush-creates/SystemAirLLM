Agents

Multi-step tasks are planned and handed between these agents. Each has one job, sees only the tools for that job, and its result must pass the listed checks before the next agent uses it. A reviewer compares the finished work with the request. Agents are defined in config/agents.yaml.

Models

The router picks a model for each task from this registry. A model is used only if it fits the hardware profile and is installed. New models are added in config/models.yaml.

Egress test

Firewall lockdown test

Run lockdown.bat to block all outbound traffic from the model server and the workbench with Windows Firewall. This test then makes one deliberate outbound attempt from the workbench itself. Without the lockdown the attempt succeeds, which is expected.

What this does and does not prove

The monitor observes the workbench and model-server processes on this machine. Code run by the agent executes in a Docker container with networking disabled, which the egress test checks. For deployment, add an outbound firewall rule or a physical air gap as the enforcing control.
